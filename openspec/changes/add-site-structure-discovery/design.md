## Context

任务组 3 已实现并对 `ccs.fjnu.edu.cn` 实测通过的采样与选择器推断链路仍然有效，本变更改变的是它被调用的**时机与作用域**，而非算法本身。动机见 `proposal.md - Why`，行为契约见 `specs/`；完整的调研过程与实测记录见 `docs/superpowers/specs/2026-09-09-site-structure-discovery-design.md`。

三条设计前实测的事实，直接约束了下面的取舍：

- `ccs`/`www`/`jwc.fjnu.edu.cn` 的 `sitemap.xml`、`robots.txt`、`rss.xml` 全部返回 404。依赖 sitemap 的"零请求摸清全站"方案对实际目标不可用，结构必须自行探出。
- 首页 `ul.nav-list` 含 31 条链接、嵌套两层，栏目名为可读中文。导航可作为栏目树的主要来源。
- 列表页无"共 N 条"文本，但分页控件暴露末页链接（`kydt` 栏目给出 `list11.htm`）。规模可在不翻页的前提下估算。

现有可复用资产：`acquire/` 下的 `robots.py`、`fetching.py`、`http_client.py`、`dom.py` 四个模块零改动可用；`selectors.py` 的推断算法（含已修正的三处缺陷）保留；`server/` 的服务骨架保留。

## Goals / Non-Goals

**Goals:**

- 让"要不要爬、爬哪些"成为看着数据做的决定
- 把探测开销压在数十个请求量级，与全站爬取的数千页形成数量级差异
- 使站点改版能在爬取失败之前被发现
- 让结构探测与抽取推断彼此独立可重跑，中间产物落盘可检查

**Non-Goals:**

- 不做全站 URL 穷举
- 不做需要浏览器渲染的视觉分区（VIPS 一类），与本地轻量运行形态冲突
- 不在探测阶段推断抽取选择器
- 不为未被勾选的范围发起任何请求

## Decisions

### 采样单位从栏目改为页面模板

探测流程分四步：抓首页还原栏目树（1 请求）→ 逐栏目抓列表首页判类型并估规模（15–30 请求）→ 按页面模板采样详情页（10–20 请求）→ 对齐落盘（0 请求）。

第三步是控制请求量的关键。实测该站 40 个栏目只对应 4–5 种页面模板，按模板采样比按栏目采样少一个数量级的请求。

**备选方案**：按栏目采样，实现更直接。但请求量随栏目数线性增长，且对共用模板的栏目做了大量重复工作。

### 栏目与模板是两个维度，不是一棵树

栏目来自导航，携带人类语义（"通知公告"而非 `/tzgg/list.htm`），层级来自导航嵌套。模板来自聚类，是机器视角。两者多对多：一个模板常被多个栏目共用，一个栏目也可能含多种模板。

勾选时两个维度都可用，取交集。这使"只要详情页不要人物页"这类意图可以表达，而单一栏目树表达不了。

**备选方案**：只做栏目树。更直观，但跨栏目的相同页面类型看不出来，抽取规则要重复配置。

### 模板聚类用结构指纹与 URL 形状的合取

只用 URL 形状会把改版后的页面误并——URL 没变但结构变了，而这恰恰是最该被发现的情况。只用结构指纹会把不同栏目的同模板页面拆开——内容差异会带来细微指纹差别。

合取更稳：两者一致才归为一类。结构指纹取页面中"标签 + class 首词"路径的集合，用 Jaccard 相似度衡量，阈值可配置。

### 规模估算按可靠性分级并记录采用的方式

四条路径依次尝试：条数文本 → 分页链接最大页码 → 倍增试探定位末页（代价 log n 个请求）→ 标记未知。

关键约束是**记录实际采用了哪一条**，并要求界面以约数呈现。估算值若以精确数字展示，使用者会据此做出它支撑不了的判断。

**刻意不做**：不为求准确而翻遍所有分页。那样探测就退化成了爬取，失去了"先看再决定"的意义。

### 正文提取引入 trafilatura，其余分区自研

正文提取是被反复评测过的成熟问题，自研投入产出比低；trafilatura 在公开评测中持续优于 readability-lxml 与 jusText，中文可用，且是单点能力库——不介入链路编排，符合已固化的"不引入 RAG 编排框架"边界（判据：该库是否试图替我们决定链路如何编排）。

它只负责正文分区。导航、页脚、侧栏、分页、条目列表、元信息、附件七类分区自研，复用 `dom.py` 已有的噪声识别并扩展。

**不引入 advertools**：为一个 URL 拆解函数引入 pandas 与整套 SEO 工具箱不划算，URL 形状归一我们已有约二十行实现。**不引入 ultimate-sitemap-parser**：目标站点全无 sitemap；保留"若有则优先"的分支，标准库解析足够。

### 分区携带置信度而非布尔判定

与推荐器的取向一致：使用者需要看到依据才能判断是否采信。正文识别失败时置信度为零并标记，但不阻止该页面参与模板归类——结构信息仍然有效。

### 结构库沿用索引层的版本指针模式

`<data_root>/<kb_id>/structure/` 下按版本存放，`current` 指向生效版本。新版本写入独立目录 → 校验非空 → 原子替换指针 → 保留上一版。重探中断只是让新版本目录成为孤儿，指针从未移动。

复用已有模式而非另造一套，理由是这两处的需求完全相同：长任务产出、可中断、失败不得破坏已有数据。

### 差异比对中"模板改版"是最重要的一类

四类差异中，新增/消失/规模变化是信息，**模板改版是警报**——它意味着基于该模板生成的抽取规则可能已失效。`design.md` 把"站点改版使选择器失效"列为主要风险，此前的应对只有抽取健康度校验这一事后手段；结构比对提供了事前发现的途径。

### 抽取推断推迟到勾选之后

推断的作用域从"整站一套"改为"每个被选中模板一套"。未被勾选的模板不推断、不请求。

这既是隐私与礼貌上的改进（不为用户不要的东西打扰目标站点），也让每套规则的样本更同质——原先整站一套选择器，在模板不一致的站点上必然有一部分字段命中率被拉低。

## Risks / Trade-offs

- **导航识别对不规范站点失效** → 退回链接聚类得出栏目候选，名称标记为未知并提示人工命名；识别结果在界面上可人工修正。
- **模板聚类过粗或过细** → 相似度阈值可配置；每个模板在界面上展示样本 URL，使用者能直接核对是否合并有误。
- **规模估算偏差** → 明确标注估算方式并以约数呈现；无法估算时标记未知而非给推测值。
- **trafilatura 对中文公文版式的表现未经验证** → 与解析库选型同理，先以真实样本核对；其调用收敛在分区模块内，替换影响面限于一个模块。
- **探测请求量随栏目数线性增长** → 请求总数上限可配置，达到上限时中止并报告未探测的栏目，而非静默截断。
- **单元测试夹具过于理想化** → 任务组 3 的三处缺陷全部因此未被捕获，直到真实站点实测才暴露。本变更要求夹具包含大体量导航、多个同名 class 的容器与正文之外的长文本块，且每个能力域完成后对真实站点做一次核对。

## Migration Plan

分四阶段，每阶段有可独立验收的产物：

1. **分区与模板** —— trafilatura 接入、八类分区识别、结构指纹与聚类。验收：对固定样本与真实详情页产出分区与模板归类。
2. **探测流程** —— 栏目树还原、页面类型判定、规模估算、请求预算。验收：对 `ccs.fjnu.edu.cn` 完成一次完整探测并人工核对栏目树。
3. **结构库** —— 落盘、版本指针、差异比对。验收：两次探测之间的四类差异可被正确报出。
4. **勾选与衔接** —— 范围勾选、抽取推断改造为按模板、配置草稿按范围生成、界面改造。验收：勾选后能得到分模板的抽取规则，未勾选部分零请求。

回滚：结构库层面由版本指针提供；抽取推断的算法未变，作用域改造可独立回退。

## Open Questions

- 界面上栏目树与模板的展示形式（树形控件 / 表格 / 两者并存）留待阶段 4 前端任务开始时确定，不影响后端契约。
- 勾选粒度是否需要支持"栏目内按日期范围筛选"，取决于爬取阶段的增量策略，留待 `web-crawling` 的增量要求实现时一并确定。
