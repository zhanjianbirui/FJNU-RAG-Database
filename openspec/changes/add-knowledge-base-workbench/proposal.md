## Why

把一堆文档变成一个能问答的知识库，今天的门槛不在技术可得性，而在**决策**：切多大、要不要 OCR、用向量还是关键词、要不要 rerank——这些参数对效果影响巨大，却没有工具告诉你该怎么选。现有产品（Dify、RAGFlow、AnythingLLM）都从"用户上传文件"开始，默认你已经知道答案；而想自动找出最优配置的那批工具（Cognita、Verba、RAGBuilder、R2R）已经归档或停更，因为实证搜索需要用户根本没有的评测集。

同时，所有主流方案都不解决**语料从哪来**。企业文档散在文件夹里还算好办，公共机构的资料散在几十个二级站点上，附件挂在页面角落——没有任何一个知识库产品处理这件事。

本项目做一个**本地运行的知识库搭建工作台**：爬取或导入 → 分析语料特征 → 基于规则给出配置建议 → 人工确认后建库 → 在界面上测试效果。定位是"把拍脑袋变成看数据"，而不是"自动找出最优配置"——建议永远带理由且可覆盖，决定权在人。

学校办事问答是它的第一个应用场景，不是它的边界；企业内部知识库用同一套流程。

## What Changes

- 新增**本地工作台**：本地起 HTTP 服务、浏览器访问，三个界面覆盖完整流程——① 数据获取与分析 ② 配置与建库 ③ 知识库测试。全部数据留在本机。
- 新增**双入口语料获取**：配置驱动的合规网页爬虫（遵守 `robots.txt`、限速、可识别 UA，**不使用反检测手段**），以及本地文件夹导入。两条入口汇入同一条处理流水线。
- 新增**站点结构分析**：采样目标站点、推断正文/标题/日期/附件的候选选择器并给出命中率，产出可编辑的站点配置草稿，让接入一个新站点不需要写代码。
- 新增**语料画像**：统计 MIME 分布、扫描件比例、表格密度、正文长度分布、模板重复率。
- 新增**规则式配置推荐**：基于画像输出建议及其**理由**——切分大小、是否需要 OCR、是否启用 BM25 混合检索、是否先去重、是否 rerank。**不做实证搜索，不承诺最优，每项建议可在界面上覆盖。**
- 新增**KnowledgeKernel 抽象**：`ingest` / `retrieve` / `delete` 三方法契约。首发一个实现——向量 + BM25 混合检索 + rerank。预留知识图谱位（界面上置灰并说明原因），不在本次实现。
- 新增**知识库测试界面**：单次提问试答、批量评测集运行、指标与逐用例结果、命中片段与来源可视化。
- 新增**多 provider 模型抽象**：Chat 与 Embedding 可独立配置为 OpenAI、DeepSeek 或本地模型，按预算与数据合规要求自选。
- 新增**办事附件直链**：命中内容关联的表格、申请书等附件，连同原始下载 URL 一并返回，无需再回到来源页面。
- 新增**单库导出服务**：建库完成后可一键启动只读问答 HTTP 服务，供外部应用（如学校自己的 app）调用。一个服务实例对应一个知识库，不做多租户。

## Capabilities

### New Capabilities
- `workbench-ui`: 本地工作台的三个界面、流程编排与状态反馈
- `site-analysis`: 站点采样、选择器推断、配置草稿生成
- `web-crawling`: 配置驱动的合规爬取、增量更新、附件下载
- `local-import`: 本地文件夹导入、类型识别、与爬取产物的统一表示
- `document-processing`: 正文提取、附件解析、元数据抽取、语义切分
- `corpus-profiling`: 语料统计画像与规则式配置推荐
- `knowledge-kernel`: KnowledgeKernel 契约、混合检索实现、索引版本管理
- `model-providers`: Chat 与 Embedding 的 provider 抽象及内置实现
- `qa-service`: 问答组装、附件直链、无依据拒答、单库导出服务
- `quality-evaluation`: 评测集格式、指标、回归判定与测试界面数据

### Modified Capabilities
（无。`openspec/specs/` 当前为空，本变更是项目的首个能力集。）

## Impact

- **代码**：全新代码库。当前仓库除脚手架、`pyproject.toml` 与 `.env.example` 外无源码。
- **依赖**：新增 `scrapling`（爬取）、`fastapi` + `uvicorn`（本地服务）、`chromadb`（向量）、`bm25s`（关键词检索）、`pypdf` / `python-docx` / `openpyxl`（附件解析）、`pyyaml`；前端构建链（Node + 打包器）。可选依赖组：`sentence-transformers`（本地嵌入与 rerank）、OCR。已有 `openai`、`deepeval`、`pydantic-settings`、`typer` 复用。
- **模型权重**：本地嵌入与 rerank 需首次下载（中文嵌入 ~96MB，rerank ~1.1GB）。默认走云端 API，本地模型按需启用，避免强制大体积下载。
- **数据**：全部落在本机——原始页面与附件、语料画像、索引、评测集。不上传任何用户文档。
- **外部系统**：读取用户指定的公开网站。合规边界写入 `web-crawling` 规格，作为可验收要求。
- **明确排除**：多租户、分布式部署、用户账号体系、桌面端打包（本次只做本地服务 + 浏览器）、需要独立服务进程的重型 RAG 引擎（与本地运行形态冲突）。
- **风险**：站点改版使选择器失效——靠站点分析工具与抽取健康度校验降低影响，而非假定结构稳定。
