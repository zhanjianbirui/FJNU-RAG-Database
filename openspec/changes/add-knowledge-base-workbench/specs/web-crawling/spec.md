## Purpose

按站点配置合规地爬取公开页面与附件，落盘原始内容与元数据，并支持增量更新，使知识库能够在不重复抓取全站的前提下保持新鲜。

## ADDED Requirements

### Requirement: 配置驱动的爬取

爬取行为 SHALL 完全由站点配置决定，包括站点清单、URL 准入与排除规则、分页规则与字段抽取选择器。接入一个新站点 MUST NOT 需要修改代码。

#### Scenario: 按配置爬取一个新站点
- **WHEN** 用户提供一份合法的新站点配置并启动爬取
- **THEN** 系统在不修改任何代码的前提下完成该校站点的爬取

#### Scenario: 配置非法
- **WHEN** 站点配置缺少必填字段或字段类型错误
- **THEN** 系统在发起任何网络请求之前中止，并报告具体的字段路径与错误原因

#### Scenario: URL 超出准入范围
- **WHEN** 页面中发现的链接不匹配配置的准入规则，或匹配排除规则
- **THEN** 系统不抓取该链接

### Requirement: 爬取合规约束

系统 MUST 遵守目标站点的 `robots.txt`，MUST 以可识别的 User-Agent 标明自身身份与联系方式，MUST 遵守配置的并发上限与请求间隔。系统 MUST NOT 使用任何反检测、指纹伪装或验证码绕过手段访问目标站点。

#### Scenario: 遵守 robots.txt
- **WHEN** 一个待抓取 URL 被目标站点 `robots.txt` 禁止
- **THEN** 系统跳过该 URL 且不发起请求，并将其记入跳过原因为 robots 的统计

#### Scenario: 遵守速率限制
- **WHEN** 配置指定了每域名的最小请求间隔与最大并发数
- **THEN** 系统对该域名的实际请求 MUST NOT 超过所配置的并发数，且相邻请求间隔 MUST NOT 小于所配置的间隔

#### Scenario: 携带可识别身份
- **WHEN** 系统向目标站点发起任何请求
- **THEN** 请求头中的 User-Agent MUST 包含项目标识与一个可供站点管理员联系的 URL 或邮箱

#### Scenario: 服务端返回限流信号
- **WHEN** 目标站点返回 429 或 503
- **THEN** 系统对该域名退避后重试，重试次数达到配置上限后放弃该 URL 并记录，而非持续施压

### Requirement: 原始内容与元数据落盘

系统 SHALL 为每个成功抓取的页面持久化其原始内容、来源 URL、抓取时间与内容哈希；页面中匹配附件规则的链接 SHALL 被下载并与来源页面关联保存。

#### Scenario: 保存页面与其附件
- **WHEN** 一个通知详情页包含一个申请表附件链接
- **THEN** 系统保存该页面的原始内容与元数据
- **AND** 下载该附件并记录其原始 URL、本地路径与所属页面

#### Scenario: 附件下载失败
- **WHEN** 附件链接返回错误或超时
- **THEN** 系统仍保留该页面及附件的原始 URL，将附件标记为未下载，并继续处理其余内容

#### Scenario: 附件超出体积上限
- **WHEN** 附件体积超过配置的上限
- **THEN** 系统跳过下载，保留其原始 URL 并记录跳过原因

### Requirement: 增量爬取

再次爬取同一站点时，系统 SHALL 依据内容哈希跳过未发生变化的页面，仅对新增或变更的页面产出更新。

#### Scenario: 页面未变更
- **WHEN** 重新抓取一个内容与上次完全相同的页面
- **THEN** 系统将其标记为未变更，不产生新的处理产物

#### Scenario: 页面已变更
- **WHEN** 重新抓取一个内容已变化的页面
- **THEN** 系统更新其存储内容、内容哈希与抓取时间，并将其标记为待重新处理

#### Scenario: 报告本次爬取结果
- **WHEN** 一次爬取运行结束
- **THEN** 系统报告新增、变更、未变更、失败与被跳过的页面数量
