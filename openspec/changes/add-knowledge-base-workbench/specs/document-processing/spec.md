## Purpose

把爬取到的原始页面与附件转换为带完整元数据的、适合检索的文本片段，并保证办事流程所需的表格附件在整个链路中始终可被追溯到其原始下载地址。

## ADDED Requirements

### Requirement: HTML 正文提取

系统 SHALL 从原始页面中提取正文文本，并 MUST 剔除导航、页眉页脚、侧边栏与广告等非正文内容。

#### Scenario: 提取通知正文
- **WHEN** 处理一个通知详情页
- **THEN** 输出的正文包含通知的完整内容
- **AND** 不包含站点导航栏与页脚版权信息

#### Scenario: 正文为空
- **WHEN** 页面按配置选择器提取到的正文为空或短于配置的最小长度
- **THEN** 系统将该页面标记为提取失败并记录原因，不将其纳入后续索引

### Requirement: 附件内容解析

系统 SHALL 解析 PDF、DOCX 与 XLSX 附件的文本内容，使其可被检索。对于无法解析的附件类型或损坏文件，系统 MUST 保留其元数据与原始链接。

#### Scenario: 解析 PDF 申请表
- **WHEN** 处理一个 PDF 格式的申请表附件
- **THEN** 系统提取其文本内容并与所属页面关联

#### Scenario: 附件类型不受支持
- **WHEN** 附件为不受支持的类型（如图片扫描件）
- **THEN** 系统跳过文本解析，但保留该附件的文件名、类型与原始下载 URL，使其仍可被作为办事材料返回

#### Scenario: 附件损坏
- **WHEN** 附件文件损坏导致解析抛错
- **THEN** 系统记录解析失败原因，保留其元数据与原始链接，并继续处理其余附件

### Requirement: 元数据抽取

每个文档 SHALL 携带来源标识、标题、发布日期、发布部门与关联附件列表。来源标识对爬取产物为原始 URL，对本地导入为文件路径。缺失的字段 MUST 显式标记为未知，MUST NOT 以猜测值填充。

#### Scenario: 完整元数据
- **WHEN** 页面中标题、发布日期与发布部门均可抽取
- **THEN** 文档元数据中三者均有值，且来源标识与页面 URL 一致

#### Scenario: 发布日期缺失
- **WHEN** 页面中无法抽取到发布日期
- **THEN** 该字段被标记为未知
- **AND** 系统不以抓取时间或当前时间代替发布日期

### Requirement: 语义切分

系统 SHALL 将文档切分为片段，切分 MUST 优先沿标题层级与段落边界进行，MUST NOT 在句子中间切断。每个片段 MUST 继承其来源文档的全部元数据，包括附件列表。

#### Scenario: 按标题层级切分
- **WHEN** 一篇办事指南包含"申请条件""所需材料""办理流程"三个小节
- **THEN** 切分结果在这些小节边界处分片，而不会把一个小节的内容与下一小节混在同一片段中间

#### Scenario: 超长段落
- **WHEN** 单个段落长度超过配置的片段上限
- **THEN** 系统在句子边界处将其拆为多个片段，且相邻片段间保留配置的重叠长度

#### Scenario: 片段保留附件可追溯性
- **WHEN** 一个文档关联了两个附件并被切分为五个片段
- **THEN** 这五个片段的元数据中均包含这两个附件的文件名与原始下载 URL
