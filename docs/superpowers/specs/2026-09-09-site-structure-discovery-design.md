# 站点结构探测：先理解，再决定爬什么

日期：2026-09-09
状态：已确认，待转实施计划
影响的能力：`site-analysis`（重写）、`web-crawling`（新增按选定范围爬取）

## 背景

原 `site-analysis` 的流程是：给一个栏目入口 URL，采样若干详情页，推断出一套
抽取选择器，生成配置草稿，然后爬。它已在任务组 3 中实现并对 `ccs.fjnu.edu.cn`
实测通过。

问题在于这条流程要求使用者**在了解站点之前就做出决定**——必须先知道"我要爬
哪个栏目"，才能给出入口 URL。而公共机构站点的资料恰恰散在几十个二级栏目里，
使用者往往不知道有哪些栏目、哪个栏目里有多少东西、值不值得爬。

新流程把顺序倒过来：先用少量请求摸清整站有什么、多大、页面长什么样，把结果
落成一份可复查的结构库；使用者据此勾选范围；只有勾选之后才推断抽取规则并爬取。

## 调研与实测结论

三条实测结论直接约束了设计，均在设计前验证：

**目标站点没有 sitemap。** `ccs.fjnu.edu.cn`、`www.fjnu.edu.cn`、`jwc.fjnu.edu.cn`
的 `/sitemap.xml`、`/robots.txt`、`/rss.xml` 全部返回 404。因此依赖 sitemap 的
"零请求摸清全站"方案（ultimate-sitemap-parser 一类）对实际目标不可用，结构必须
自行探出。保留"若站点提供 sitemap 则优先使用"的分支，但不作为主路径。

**导航可用作栏目树来源。** 首页的 `ul.nav-list` 含 31 条链接，栏目名为人类可读
的中文（学院概况、师资队伍、通知公告……），嵌套 `ul` 有 2 层，层级信息完整。

**规模可在不翻页的前提下估算。** 列表页没有"共 N 条"文本，但分页控件暴露了
`list2.htm` 与 `list11.htm`——后者即末页。取分页链接中的最大页码即可得到页数，
乘以首页条目数得到规模估算。

## Goals / Non-Goals

**Goals**

- 用数十个请求（而非全站爬取）产出整站的栏目树、页面模板与规模估算
- 让使用者在勾选范围之前就能看到"有什么、多大、能不能抽出想要的字段"
- 结构落盘并支持重探比对，使站点改版可被发现而非等到爬取失败率升高
- 抽取规则的推断推迟到勾选之后，未选中的部分不产生额外请求
- 复用任务组 3 已完成的合规抓取设施，不推翻重来

**Non-Goals**

- 不做全站 URL 穷举。结构是抽样与推断的结果，规模是估算值并如此标注
- 不做站点视觉渲染分析（VIPS 一类需要浏览器的方案），与本地轻量运行形态冲突
- 不在探测阶段推断抽取选择器
- 不引入 RAG 编排框架（沿用已固化的边界决策）

## 流程反转

```
旧：入口 URL → 采样详情页 → 推断选择器 → 配置草稿 → 爬取
新：入口 URL → 探测整站结构 → 结构库 → 使用者勾选 → 推断抽取规则 → 爬取
```

核心差别是**抽取规则的推断从探测阶段挪到勾选之后**。探测阶段只回答"这站有
什么、多大、页面长什么样"，不回答"怎么抽"。使用者不勾选的栏目，不会为它多
抓一个详情页。

这同时降低了对目标站点的压力：原流程为了推断选择器，必须对每个候选栏目采样
多个详情页；新流程按页面模板采样，实测该站 40 个栏目只对应 4–5 种模板。

## 数据模型

四层，两个维度：

```
Site                 host、探测时间、版本号、入口 URL
 └─ Column           栏目名、URL、父栏目、页面类型、规模估算、置信度
      ↕ 多对多
    PageTemplate     DOM 指纹、样本 URL、分区列表、覆盖的栏目
      └─ Region      类型、选择器、置信度
```

**Column（栏目）** 来自导航，携带人类语义：名称是"通知公告"而不是
`/tzgg/list.htm`。层级来自导航的嵌套结构。

**PageTemplate（页面模板）** 来自聚类，是机器视角：结构相同的页面归为一类，
无论它们属于哪个栏目。

两者是多对多：一个模板常被多个栏目共用（通知公告与科研动态往往同模板），一个
栏目也可能包含多种模板（列表页与详情页）。使用者勾选时两个维度都可用——既能
说"要通知公告栏目"，也能说"只要详情页模板，不要人物页模板"。

**Region（分区）** 的类型集合是封闭的：

| 类型 | 含义 |
|---|---|
| `navigation` | 站点导航与栏目菜单 |
| `article_body` | 正文区 |
| `article_meta` | 标题、发布日期、发布部门所在区 |
| `article_list` | 列表页的条目列表区 |
| `pagination` | 分页控件 |
| `attachment` | 附件链接区 |
| `footer` | 页脚与版权 |
| `sidebar` | 侧栏 |

分区携带置信度而非布尔判定，理由与选择器候选相同：使用者需要看到依据才能判断
是否采信。

## 探测流程

四步，合计约 25–50 个请求（分步预算见下表），遵守既有的 robots 判定与限速。
总请求数上限可配置，超出时按导航顺序截断并在结果中提示未探完的栏目。

**① 栏目树骨架（1 请求）**

抓首页，定位导航容器（候选：`<nav>`、class/id 含 nav/menu 的元素，取其中链接
最多者），按嵌套 `ul` 还原层级，产出栏目树骨架。

导航识别失败时退回广度优先遍历：从首页取所有同源链接，按 URL 形状聚类，每类
取一个代表作为"栏目"，名称标为未知并提示需人工命名。

**② 栏目探查（15–30 请求）**

每个栏目抓其 URL 指向的第一页，判断页面类型：

- 页面含重复结构的链接列表且有分页控件 → `list`（列表页）
- 页面含单一正文区且无列表 → `single`（单页）
- 二者皆不成立 → `unknown`，标记需人工确认

同时从分页控件读取规模（见下节）。

**③ 模板采样（10–20 请求）**

把②收集到的详情页链接按 URL 形状分组，每组抓 1–2 个样本，对样本做分区并计算
DOM 指纹，据此聚类成页面模板。

这是省请求的关键：采样单位是**模板**而非栏目。

**④ 对齐与落盘（0 请求）**

把模板挂回栏目，写入结构库。

同时为每个栏目计算**字段把握度**：取该栏目所用模板中 `article_body`、
`article_meta`、`attachment` 三个分区的置信度，按"全部识别出"/"部分识别出"/
"均未识别出"归为高、中、低三档。这是给使用者的采信提示，不是精确指标，界面上
按三档展示而非展示原始分值。

## 页面分区与模板聚类

**正文与去噪引入 [trafilatura](https://github.com/adbar/trafilatura)。** 它是
单点能力库，只做"从一张网页里找出正文"，不介入链路编排，符合已固化的框架边界
决策。选它的理由是正文提取是成熟且被反复评测过的问题，自研的投入产出比低；它
在公开评测中持续优于 readability-lxml 与 jusText，且中文可用。

trafilatura 只负责 `article_body`。其余分区自研，复用已有的 `dom.py`：

- `navigation` / `footer` / `sidebar`：class/id 关键词 + 链接密度
- `pagination`：含连续数字文本的链接簇，或匹配分页 URL 形状的链接簇
- `article_list`：重复结构的链接列表（同一标签路径出现 5 次以上）
- `article_meta`：正文区之前、含日期正则或短标题的元素
- `attachment`：指向文档类扩展名的链接

**模板聚类判据是 DOM 标签路径指纹与 URL 形状的合取**——两者一致才归为一类。

只用 URL 形状会把改版后的页面误并（URL 没变但结构变了），只用 DOM 指纹会把
不同栏目的同模板页面拆开（结构相同但内容差异导致细微指纹差别）。合取更稳。

DOM 指纹的定义：取页面中所有元素的"标签 + class 首词"路径，去重后取集合，
两个页面的指纹相似度用 Jaccard 系数衡量，超过阈值即同一模板。

## 规模估算

按可靠性从高到低依次尝试，并记录实际采用的方式：

1. **条数文本**：匹配"共 N 条""共 N 页""N/M 页""总数：N"等中文 CMS 常见写法
2. **分页链接最大页码**：从分页区链接中提取页码，取最大值（实测该站 `kydt` 栏目
   给出 `list11.htm`，即 11 页）
3. **倍增探测**：当只存在"下一页"而无页码时，按 2、4、8… 试探页码直到 404 或
   空列表，再二分收敛边界。代价为 log n 个请求
4. **无法确定**：标记为未知，不给推测值

条目数 = 页数 × 首页条目数，**明确标注为估算值**。规格中要求界面上以"约"字或
等价方式呈现，不得显示为精确数字。

## 结构库

```
<data_root>/<kb_id>/structure/
├── current            指向生效版本
├── v1/site.json       2026-09-01 探测
└── v2/site.json       2026-09-09 探测
```

沿用索引层已有的版本指针模式：新版本写入独立目录，校验非空后原子替换指针，
保留上一版。重探失败或中断时指针不动。

**差异比对**在两个版本之间进行，产出四类变化：

| 记号 | 含义 |
|---|---|
| `+` | 新增栏目或模板 |
| `−` | 消失的栏目 |
| `~` | 规模变化 |
| `!` | 模板结构已变，基于它生成的抽取规则可能失效 |

`!` 是最重要的一类：design.md 已把"站点改版使选择器失效"列为主要风险，此前的
应对只有"抽取健康度校验"这一事后手段，结构比对提供了事前发现的途径。

## 库选型

| 库 | 决定 | 理由 |
|---|---|---|
| trafilatura | 引入 | 正文提取与去噪的成熟实现，单点能力库 |
| ultimate-sitemap-parser | 不引入 | 目标站点全无 sitemap；保留"若有则优先"分支，标准库解析足够 |
| advertools | 不引入 | 为 `url_to_df` 一个函数引入 pandas 与整套 SEO 工具箱不划算；URL 形状归一已有约二十行实现 |
| readability-lxml / jusText | 不引入 | 能力被 trafilatura 覆盖 |

## 错误处理

- **导航识别失败** → 退回广度优先遍历，栏目名标为未知，提示需人工命名
- **单个栏目探查失败** → 记录失败原因，该栏目标为未知类型，不中断整次探测
- **正文提取失败** → 该分区置信度为零并标记，不阻止模板成立
- **规模无法确定** → 标记为未知，不给推测值
- **robots 禁止** → 该栏目不发起请求，连同命中的规则一并呈现

沿用已确立的取向：失败要显性，不以推测值填补空缺。

## 测试策略

- 单元测试用固定 HTML 夹具覆盖各分区识别、模板聚类、规模估算的四条路径
- **夹具必须复刻真实页面的复杂度**：任务组 3 的教训是三个缺陷全部因夹具过于
  理想化而未被单元测试捕获，直到对真实站点实测才暴露。夹具需包含大体量导航、
  多个同名 class 的容器、以及正文之外的长文本块
- 每个能力域完成后对 `ccs.fjnu.edu.cn` 做一次真实探测并人工核对结果
- 差异比对以两份构造的结构快照验证四类变化

## 风险

- **导航识别对不规范站点失效** → 有 BFS 退路；识别结果在界面上可人工修正
- **模板聚类过粗或过细** → 相似度阈值可配置；界面展示每个模板的样本 URL，
  使用者能看出是否合并有误
- **规模估算偏差** → 明确标注为估算并记录采用的估算方式，使用者可据此判断
- **trafilatura 对中文公文版式的表现未经验证** → 与解析库选型同理，先以真实
  样本核对；其调用收敛在分区模块内，替换影响面有限
- **探测请求量随栏目数线性增长** → 栏目数上限可配置，超出时按导航顺序截断并
  提示

## 未决问题
